# 临床病例报告 → 三模块结构化抽取

## Purpose
把一批中文临床病例报告 PDF 转成统一 schema 的行数据，供 vet_agent 等兽医 AI 的
测试/评测集使用。核心纪律：**所有内容完全取自原文，缺失留空，绝不编造、不改写、不推理、不翻译。**
推理/临床意义/神经学定位等"AI 该自己推导的信息"剥离到「备注」栏，便于测试结果审核。

## When to use
- 用户给了一批兽医临床病例报告 PDF，要抽成表格。
- 用户提到"病例报告抽取""病例数据表格""测试集病例"等。
- 要补抽空 PDF、修复治疗栏泄漏、或复查抽取质量。

## Environment（关键坑，先读）
- 用独立 **Python 虚拟环境（venv）**（`python -m venv .venv` 建好，pip 装包进该 env，禁止全局装）。
- **PDF 文本抽取引擎选型**：
  - `pdfplumber` 对**部分中文兽医 PDF 会返回空文本**（编码/字体问题），不要默认用它做全量。
  - 优先用 **PyMuPDF (`fitz`)**：`pip install pymupdf`，`doc.load_page(i).get_text()`。
    本工作流实测 110 篇里 pdfplumber 失败的 6 篇，PyMuPDF 全部能干净抽出（比 OCR 更准、无识别错误）。
  - **图像型页（无文字层）和字体损坏页都必须上 OCR**：这类页 PyMuPDF 不是抽空就是抽成**乱码**
    （字形编码损坏，肉眼不可读）。典型如《犬心脏黏液肉瘤病例报告》整篇乱码、《犬输尿管囊肿诊治病例》
    p1-2 是纯图（fitz `get_text()` 直接返回空）。此时 `pip install rapidocr-onnxruntime`，
    逐页 `page.get_pixmap(dpi=300)` 渲染后 `RapidOCR()` 识别——实测能干净还原正文与图版说明。
    **不要因为 fitz 抽了"非空但乱码"就当成功**，要肉眼扫一遍输出是否有大量不可读字符。
  - 期刊合订本里目标文章常嵌在别的文章之后（首页是猪/鹿病等），按标题关键词在全文检索定位。
- 并行抽取派 **general-purpose 子 agent**：每批 ~14 篇，各读 `EXTRACTION_SPEC.md` + 本批文件名清单 +
  对应 txt，产出合法 JSON（`json.dump(obj, f, ensure_ascii=False, indent=2)`）。
  ⚠️ **扫描整本书时每批收紧到 6~10 例**，并要求**增量落盘**（每例写完即覆盖写目标 JSON），
  否则大批次子 agent 会在中途被截断（详见下文「分批抽取与防截断」）。
- **整本扫描书**（无文字层、上百例）另有一套管线：250dpi 渲染 + RapidOCR + **双栏坐标还原** + 断点续跑；
  并发 3 进程为最优。完整标定值与陷阱清单见下文「书籍 / 译著适配」。

## 字段口径（9 列，顺序固定）
`source | year | title | medical_history | medical_test | medical_treatment | Dx | follow-up | 备注`

- **source**：仅填中文刊名（如"中国兽医杂志"）。除非只能抽到英文刊名才填英文。
- **year**：`发表年（收稿年）`。能从正文/页眉找到收稿日期则写为 `2008（2007）`；
  正文无收稿日期只写发表年。刊期年 = 发表年。
- **title**：病例报告标题（= PDF 文件名去 `.pdf`，保持原样）。
- **medical_history**：signalment（动物基本信息）+ CC（主诉/直接就诊原因）+ 现病史/既往史 + **一般体格检查（PE）**。**一般体格检查结果归入本列**，含体温/脉搏/呼吸/CRT/BCS/体况评分/可视黏膜/心肺听诊/心杂音/腹部触诊/体表淋巴结等。按原文顺序拼接、不改写。允许保留**外院诊断**（临床实际可获信息）。
- **medical_test**：MDB（血常规 CBC + 生化 + 尿检）+ imaging（X/US/CT/MRI/Echo）+ **神经学检查客观发现**（四肢本体感受、共济失调、上运动神经元症状、反射等）+ other（细胞学、病理、**专科检查**如眼科检查/口腔检查等需设备/采样完成者）。
  **只写检查项目+结果，不写提示/临床意义/推理**（如"提示再生性贫血""疑似血支原体"全部删去）。
  **一般体格检查不归入本列**——它们属 medical_history（见上）；**神经学定位结论**（如"病变定位于…"）剥到备注。
  **注意**：原文常把"体格检查：…。实验室检验：…"连写，子 agent 易把整段塞进 test；须把"体格检查："标签及其查体内容拆出移入 medical_history，"实验室/血常规/影像/神经学/专科检查"部分留本列。
- **medical_treatment**：Tx 方案 + 手术/处置细节 + Rx 药物。**不含任何随访/结果/回访内容**（"1个月后死亡"
  "2周后复查好转"等全入 follow-up）。Rx 频率/途径统一术语：`po/iv/im` + `bid/tid/sid`（"2次/d"→bid）。
- **Dx**：诊断结论，格式 `物种+疾病名称`，**物种与疾病之间不空格**（如 `犬血支原体感染`、`猫甲状腺机能亢进`）；
  缩写先全称后括号（`犬颈椎C4~C5水合髓核脱出（HNPE）`）。细则见下「Dx 书写五则」。
  - **排序**：主要 / 最重要疾病写在**第一个**，且**只在开头写一次物种**（如 `犬医源性肾上腺皮质机能亢进`）。
  - **分号**：**并发 / 继发 / 多病诊断**用中文分号 `；` 间隔，不写逗号罗列、不把次要诊断塞进括号。
    例：`马产后败血症/子宫炎；继发肌肉损伤`、`犬骨肉瘤（肱骨近端）；肺转移`。
- **follow-up**：治疗结果 + 回访结果（含复诊、转归、死亡、康复时间线）。
- **备注**：从原文剥离的"提示/临床意义/疑似印象/神经学定位/病因推测"等诊断推理信息，集中存放，
  便于 AI 测试结果审核，也避免污染上述各列。

## Dx 书写五则（物种前置 + 括号去留判别，2026-09-30 定稿）

1. **物种前置、不空格**：`犬…` / `猫…` / `马…`，物种与病名之间**不加空格**，且**整行只在最前面写一次**物种。
2. **主病在前**：主要 / 最重要疾病写在第一个；次要、并发、继发诊断排后。
3. **分号间隔**：并发 / 继发 / 多病诊断一律用中文分号 `；`，**不用逗号罗列**。继发关系显式写「继发」。
4. **括号判别（关键）**——按括号内容性质三分：
   - **保留**：括号是**解剖部位 / 独立限定词** → 留在病名后。
     `犬 骨肉瘤（肱骨近端）` → `犬骨肉瘤（肱骨近端）`
   - **移入备注**：括号是**解读性 / 解释性 / 化验指标描述 / 鉴别说明**（非独立诊断），整段移入「备注」，Dx 只留病名。
     `犬 创伤后肝细胞损伤（ALT/AST 一过性升高；幼龄大型犬 ALP 轻度升高为骨骼生长期正常；非原发性肝胆疾病）`
     → Dx=`犬创伤后肝细胞损伤`；括号内全部内容入「备注」。
   - **并入病名（取规范名）**：括号内是**同一疾病的更规范 / 更准确的诊断名** → 用括号内病名替换外层俗称，去掉括号。
     `犬 皮质类固醇性肝病（医源性肾上腺皮质机能亢进）` → `犬医源性肾上腺皮质机能亢进`
   - **继发句里的非诊断项丢弃**：括号内若混有**症状/体征**（厌食、应激、消瘦、发热等），只取真正的诊断，
     症状不列为诊断。`马 产后败血症/子宫炎（继发肌肉损伤、厌食、应激）` → `马产后败血症/子宫炎；继发肌肉损伤`
5. **缩写**：先全称后括号（`犬颈椎C4~C5水合髓核脱出（HNPE）`）；诊断标准名照录原文，不改写。

## 书籍 / 译著适配（以《兽医临床病例分析》Sharkey & Radin 第2版 夏兆飞 主译 为例）
扫描图版型兽医书籍（无文字层、需 OCR）与期刊病例报告结构不同，按以下口径覆盖默认 9 列 schema：

### Schema（7 列，删 source / year）
`title | medical_history | medical_test | medical_treatment | Dx | follow-up | 备注`
书籍无「刊名 / 发表年」概念，**source 与 year 两列直接删除**，不做替代填充。

### 全书结构与取数位置（关键）
本书版式固定，各模块**来源明确**，务必按位置取，不要跨段乱抓：

| 字段 | 取数位置 |
|---|---|
| **title** | 小节 heading：`病例N[一\-—－]等级X`。写「**章节名 + 病例x + 等级x**」，如 `第二章 肝酶升高 · 病例1 等级1`。章节名取当前章标题。 |
| **medical_history** | heading 之后、首个检验表标题（`血常规检查`/`生化检查`/`尿液分析`/`腹腔液分析`…）或 `解析` **之前**的叙述段（signalment + 主诉 + 现病史 + 体格检查）。 |
| **medical_test** | ① **识别图片**：检验数值表是**图版**（血常规检查 / 生化检查 / 尿液分析 … 表框内数值 + 参考区间），逐行 OCR 识别；② **「解析」小标题下**明确陈述的客观异常结果（CBC/生化/尿液/腹腔液/影像/细胞学/病理）。**纯判读推理不入 test**。 |
| **medical_treatment** | 叙述段与「病例总结…」里的 Tx + 手术 + Rx。**本书很多病例无治疗**（纯诊断/判读教学），原文未给**直接留空**。 |
| **Dx** | **「病例总结」小标题下**（`病例总结和结果` / `病例总结及结果` / `病例总结和结论` / `病例总结` 等，OCR 可能略有出入）抽取；按「Dx 书写五则」整理。 |
| **follow-up** | 同上「病例总结」段内的**结果 / 转归 / 回访 / 后续**信息。原文未给则留空。 |
| **备注** | 被剥离的判读推理、Dx 括号内解读性内容、OCR 存疑说明、病例间对比提示。 |

### 硬纪律
- **逐字取自原文，绝不改写 / 编撰 / 句式重写 / 翻译**。仅允许合并原段换行、去掉 OCR 噪音空格。
- **不强制三模块齐全**：很多病例只有 history + test + 解析（判读教学，无治疗无随访）。**没有的模块直接留空**，不写「无」「未提及」「不适用」。
- **推理 / 解读剥离**：`解析` 段里带「提示 / 符合 / 疑似 / 考虑 / 表明 / 说明 / 推断 / 可能」的结论句 → 备注；
  test 只留「检查项目 + 客观结果」。
- **test 数值 OCR 存疑时**，以「解析」所述定性 / 倍数描述为准（如「ALP 升高 2.5 倍」），不强行填可疑数字；并在备注注明 OCR 存疑。
- **本书主打检验解读**（肝酶、胃肠道、血清蛋白、肾功能、钙磷镁、电解质酸碱），病例的临床处置往往极简，
  抽取时**严抓「有就是有、无就是空」**，不要把「解析」里的假设性诊疗建议当作实际 treatment。

### OCR 管线（扫描书专用，实战标定值）
整本书是**扫描图版**（PyMuPDF `get_text()` 全书 0 字节）时，走这条链：

1. **渲染**：`page.get_pixmap(dpi=250)`。实测**渲染只要 0.4~0.5 s/页**，全不是瓶颈。
2. **识别**：`RapidOCR()` 逐页 OCR。**瓶颈全在推理**，实测 **8~11 s/页**（单进程）。
3. **并发**：8 核机器开 **3 个进程**最稳。**并行收益为负**——4~6 进程与 3 进程同速甚至更慢，
   是**内存带宽**瓶颈而非 CPU（已用 4 进程纯 CPU 跑分验证多核可用，排除"核不够"）。
   另需给 onnxruntime 限线程（`SessionOptions.intra/inter_op_num_threads`），否则线程争抢更糟。
4. **断点续跑**：脚本**先查目标文件是否已存在再跳过**。任务中断后重跑即可续，不必从头。
5. **优化配置**（写进 `rapidocr_onnxruntime/config.yaml`）：`use_angle_cls: false`、`rec_batch_num: 16`。
6. **页码偏移**：PDF 页索引 = 书内页码 + offset（本书 offset=11，`p012` = 书页 1）。
   **务必先用目录页确认 offset**，各书不同。

### 双栏版面还原（关键，否则文本行会交错）
扫描书正文多为**双栏**，直接按 OCR 输出顺序落盘会把左右栏句子交错成读不通的乱码。
必须**按检测框 x 坐标分栏**再各自按 y 排序：

- OCR 返回的每个框带四角坐标。取 `min(x)/min(y)`，按 x 中点切**左栏 / 右栏**（栏间有空白带，
  实测本书左栏 x≈120–860、右栏 x≈925–1660），跨全宽的表格另判为**通栏**。
- 每栏内部按 y 升序拼接 → 输出用 `[[左栏]] / [[右栏]] / [[通栏]]` 标记分段，
  后续读文本包时能一眼看清版面归属。
- 检验表常出现「**左栏=项目名、右栏=数值+参考区间**」被拆到两列的情形，靠栏标记 + 页图对齐还原。

### 章节与病例边界识别
- **标题正则**：整行基本只有 `病例N[一\-—－~、]?等级X` 才算标题（`一` 常是破折号 OCR 残留）。
  写成"整行匹配"而非"包含匹配"，可挡掉正文交叉引用（如「见第二章病例9（犬）」「第五章，病例5」）。
- **等级 OCR 常出错**（如「等级13」实为「等级3」），**必须回看图版核对**，不要信文本层数字。
- **病例号连续性自检**：按章统计 `1..max` 是否缺号，缺号必回查（多为标题行 OCR 丢失或误判）。
- 一个病例的页码范围 = 本病例标题 → 下一病例标题之前。

### 给子 agent 的输入：病例文本包 + 页图
逐病例生成 `cases/case_<章>_<例>.txt`，**文件头写明元数据**（章节名 / 病例号 / 等级 / 页码范围 / 页图路径），
正文按 `--- PDF第N页 ---` + 栏标记组织。同时把全书页渲染成 `pages_img/pNNN.png` 供核对。
子 agent 拿到"文本包为主、页图为辅"的组合，才不必自己再翻 PDF。

### 分批抽取与防截断（血泪教训）
- 每批 **6~10 例**为宜。**>10 例时子 agent 极易在中途被截断**（产出 JSON 未闭合 / 构建脚本写到一半）。
- **强制增量落盘**：在派发指令里明确「**每完成 1 例就把当前累积 rows 整体覆盖写入目标 JSON**」，
  不要"全部做完再写"。这样即使中断也只丢当前那一例。
- **截断抢救**：子 agent 若留下了 `build_*.py` 构建脚本（数据内嵌在脚本里），可用"截取到最后一例完整处
  + 补写落盘尾巴"的方式**抢救出已完成的行**，再只补抽剩余几例，避免全批重跑。
- 子 agent 必须**用 Read 复核自己写出的 JSON** 并回报对象数；主 agent 合并前再统一校验。

### 数值表 OCR 陷阱清单（逐条必查）
| 陷阱 | 表现 | 处置 |
|---|---|---|
| 量级指数错 | `×10⁹` 认成 `×10¹²`（或反之） | 对照参考区间量级判断，页图确认 |
| 前导「1」伪影 | 值前多出 `1`（`HGB 111.5`、`PCV 134%`） | 页图确认后去掉 |
| 项目名整列错位 | 数值整体上/下移一行 | 必须回页图逐格对齐，**不可按文本顺序硬配** |
| 字母形近 | `GGT→GCT`、`TG→TGA`、`Mg→Ma`、`TP→TB` | 依参考区间与上下文判定，备注注明 |
| 术语错字 | `户检→尸检`、`地西洋→地西泮`、`波尼松→泼尼松`、`烧骨→桡骨`、`镔骨→髌骨`、`未非→非` | 按学科常识更正，备注注明 |
| 参考区间印刷异常 | 区间与数值矛盾（如 `TG ↑1910 (20~100)` 单位 g/dL） | **照录不改**，备注注明「原书/页图如此」 |
| 单位混用 | 同书 `mg/dL` 与 `mg/mL` 混排 | 按参考区间推断，照录并在备注说明 |

### 合并与自动 QA（脚本化，交付前必跑）
- **合并**：`glob('rows/rows_*.json')` → 按「章序号 + 病例号」排序 → 写 7 列 xlsx + 说明页。
  ⚠️ 目录里若残留 `rows_*_part.json` 之类的抢救文件，**先确认不会与正式批次重复计数**。
- **QA 脚本至少查五项**：
  1. **等级一致性**：逐行 title 的等级 vs `index.json` 的等级，零错配才过；
  2. **覆盖完整性**：按章比对「实抽病例号集合」vs「索引病例号集合」，查缺号/重号；
  3. **空值统计**：分别统计 treatment / Dx / follow-up 空值数，与书籍性质预期比对
     （纯判读教学书：这三列空值多在 10%~20%，属正常）；
  4. **占位符扫描**：`无 / 未提及 / 未见 / 不适用 / N/A / —` 整格命中即报错；
  5. **Dx 格式**：物种前缀（**物种表要够长**，含驴/美洲驼/雪貂/山羊/羊驼/豚鼠等，
     否则会把「驴尿道梗阻」「美洲驼肝胆管疾病」误报为"非物种开头"）、物种后无空格、多诊断用 `；` 而非 `，`。

### 交付
- 文件名遵循用户命名约定：`<代号><日期YYYYMMDD><书名>_<用途>.xlsx`（如 `SampleBatch_261009兽医临床病例分析_全书病例结构化抽取.xlsx`）。
- xlsx 两个 sheet：`病例数据`（7 列，冻结首行、自动换行）+ `说明`（来源、字段口径、Dx 规则、OCR 管线、纪律）。
- 交付时**主动列出存疑点**（如某例原文无某关键词而用户示例里有 → 请用户拍板），不要默默自行取舍。


## 字段校准规则（实战沉淀，合并/QA 后必查）
以下三条是多次返工后固化的口径，交付前逐条过一遍：

1. **推理/解读剥离（原文事实 + 推理 拆开）**
   - 事实列（history / test / treatment / follow-up）里凡带「提示 / 符合 / 疑似 / 不排除 / 初步排除 /
     由此推断 / 结合临床初步诊断 / 初诊考虑 / 初步诊断 / 初步怀疑 / 初步考虑 / 鉴别诊断不能排除 /
     分析可能是 / 暂时排除 / 可能与」等**结论性推理或检验解读**的整句，剥到该行「备注」，前缀 `【原文推理/解读剥离】`。
   - **Tier C 保留**：他院/外院/主人/既往的「怀疑/疑似」（如"外院怀疑为口鼻瘘""主人因怀疑被咬伤"
     "既往曾诊断肾上腺皮质机能亢进并服药"）属转诊/主诉背景，**原样留事实列**，不剥。
   - Dx / title / source 不动（诊断标签与源标题保持原样）。
   - 剥后务必清掉语病残片（"X线整体。""同时超声也。""ACTH刺激试验结果。"等），再肉眼扫一遍。
   - 标点差异（"；"vs"。"）会导致漏匹配，脚本须对每处 marker 容错或逐条核对。

2. **诊断性操作归 test、既往史留 history**
   - 本次就诊的**诊断性操作**（切除活检、穿刺送检、开腹/开胸探查取材）及其病理/细胞学结果 → `medical_test`。
   - 他院/既往的**手术与诊断结论**作为既往史 → `medical_history`（如"4个月前右侧嘴唇肿块手术切除，
     病理报告纤维肉瘤1级""2021年脾脏肿物摘除+组织病理学诊断血管肉瘤"）。
   - 区分点："本次就诊做的诊断操作" vs "来院前已发生的诊疗经过"。

3. **剖检结果全部放 follow-up**
   - **死后剖检 / 尸检 / 安乐死后剖检**及其伴随的**组织学检查、尸体实验室检验**结果 → `follow-up`
     （例：row55 安乐死+死后剖检+细胞学+组织病理学；row88 脾脏血管瘤破裂死亡，剖检+眼观+镜检+免疫组化全入 follow-up；
     row114 安乐死后剖检+涂片镜检弓形滋养体）。
   - **术中探查（存活动物）与离体标本肉眼检查**属诊疗检验 → 留在 `medical_test`
     （例：row22 仔犬开腹探查"肠穿刺抽出肠内容物、回回肠闭锁"；row74 截肢后"离体组织剖检"眼观囊腔）。
   - 区分点："动物已死亡后的尸体剖检" vs "存活/术中的探查与标本检查"。前者转 follow-up，后者留 test。
   - 若某行 test 整格都是剖检内容（如 row88/101/104/114），挪空后 test 留空属正常。

## Workflow（标准管线）
1. **清单**：用 `Get-ChildItem -Filter *.pdf`（**不要用 Glob**，它有 100 条上限会漏数）统计真实 PDF 数，存 `pdf_list.txt`。
2. **预抽取**：PyMuPDF 把每篇抽成 `pdf_text_all/<文件名>.txt`（后台跑，110 篇约 1 分钟）。
3. **Pilot 审核**（可选但推荐）：先抽 3–5 篇（含一例多病例、一例含手术/MRI）做草稿表给用户审字段映射。
4. **批次拆分**：110 篇拆 8 批（每批 ~14），写 `batch_NN.txt` 文件名清单 + `EXTRACTION_SPEC.md`。
5. **并行子 agent**：每批一个 general-purpose agent，按 spec 抽 9 字段，每篇（多例每例一行）写 `rows_NN.json`。
6. **合并 + 已审覆盖**：`merge_all.py` 合并 8 个 JSON；用已审 pilot 的 N 行**覆盖**同名篇，确保口径生效。
7. **QA**：
   - 验证已审覆盖生效；统计空 Dx/空治疗/空检验。
   - 扫描治疗栏是否残留随访关键词（死亡/复查/回访/改善/好转/消退/复发/痊愈/带回家/临床症状消失）；
     命中者把结果句移到 follow-up，治疗栏只留治疗。
   - 标记空 PDF（PyMuPDF 抽空）→ 换引擎重抽补行（见下）。
   - 标记"文件名与内容不符"的串扰行（如"犬输尿管囊肿"实为红细胞增多症）→ 去重/改正。

## 空 PDF / 重抽补行 SOP
- 若某篇 PyMuPDF 抽空：先确认是否真图像（PyMuPDF `text_len<50`）。
- 若是合订本混排导致定位失败：全文检索标题关键词，截取目标文章段落即可（无需 OCR）。
- 若真图像 **或字体损坏乱码**：渲染 300 dpi + rapidocr 识别，存 `pdf_text_ocr/`，再人工按 schema 抽取。
  - 字体损坏页的图版说明（"图N：……""HE 染色"）往往比正文更易读，可据此回推影像/病理/免疫组化结果；
    但 **history / treatment / follow-up 若无法可靠抽取必须留空**，并在备注注明 OCR 损坏 + 混排情况，**绝不编造**。
- 回填策略：总表里**已有空行**则按标题精确匹配更新；**无该行**（子 agent 拿到空文本没产行）则追加新行，避免重复。

## 错乱行定位 & 删行回填（易踩坑）
- **串扰/错乱行按"备注关键词"定位，勿信初版行号**。例：「犬输尿管囊肿诊治病例」PDF 实际混进了
  「犬真性红细胞增多症」内容，初抽时落在 row100，但按"文件名不符"备注定位实为 row97。
  脚本用 `备注含某关键词` 而非硬编码行号来 `setrow` 覆盖，才稳。
- **删行后用 `delete_rows` 并 reindex 再回填**。openpyxl `ws.delete_rows(n)` 后下方行上移，
  原本 row118/119 的真实条目会变 row115/116；若删行后还按旧行号回填会写错位置。
  实践：删行前先记录"被删行 vs 其重复真实行"的映射（如 row61=空占位 ↔ row118=真实洋葱中毒），
  删完确认 max_row，再用标题/备注关键词定位真实行回填，不依赖旧行号。
- **删前必核验"空占位 vs 真实重复"**：同一标题可能既有 0 字节空行、又有 PyMuPDF 补回的真实行
  （如洋葱中毒、肠绞窄）。删的是空占位，真实行要保留——扫全文确认被删关键词是否仍作为**真实病例内容**
  出现（如 row19「复合麻醉」是唾液腺炎真实病例的术式麻醉提及，非被删的麻醉实验论文）。

## QA 清单（交付前自检）
- [ ] 多病例是否每例一行（history 以"病例N："开头区分）
- [ ] 缺失字段是否留空（不是"无"也不是编造）
- [ ] 是否夹带原文外内容（推理/翻译/补充）
- [ ] 治疗栏是否混入随访/结果
- [ ] 神经学定位/临床意义是否只在备注
- [ ] 一般体格检查（体温/脉搏/呼吸/CRT/BCS/黏膜/心肺听诊/腹部触诊/体表淋巴结）是否在 medical_history、未混入 medical_test；神经学检查客观发现是否在 medical_test；专科检查（眼科/口腔等）是否在 medical_test
- [ ] Rx 是否统一 po/iv/im + bid/tid/sid
- [ ] Dx 是否 物种+疾病 书面格式、缩写先全称后括号
- [ ] source 是否仅中文刊名；year 是否 发表（收稿）
- [ ] **（书籍）** title 是否为「章节名 · 病例x 等级y」，且等级与索引逐行一致（零错配）
- [ ] **（书籍）** 病例号是否按章连续无缺号、无重号；总数与索引一致
- [ ] **（书籍）** 检验表数值是否已按**页图**逐格对齐（尤其项目名整列错位、×10¹²/×10⁹、前导「1」伪影）
- [ ] **（书籍）** 数值表的 `解析` 推理是否只存在于「备注」，test 里只剩「项目+客观结果」
- [ ] **（书籍）** 原书印刷/OCR 异常是否**照录**并在备注注明，而非擅自"修正"成合理值
- [ ] 交付前是否**主动列出存疑点**请用户拍板（而非默默自行取舍）
